# MORIZON Reloaded Claude開発引継ぎ書

作成日: 2026-09-17  
引継ぎ対象: MORIZON Reloaded v2.3.0-rc2  
開発主体: 和田陽一氏による個人的な技術的取組

## 1. 引継ぎの目的

旧「もりぞん」を現行QGISで継続利用できるようにしたMORIZON Reloadedについて、ChatGPT/Codex中心の改修からClaude/Claude Code中心の開発へ移行する。Claudeは、rc2を壊さずに検証可能な状態へ整え、外部動作確認を経て正式版v2.3.0の公開判断に必要な材料を揃える。

## 2. 現在地（確定）

- 正本候補ソース: `MORIZON_Reloaded_QGIS344_v2.3.0-rc2.zip`
- プラグイン内部版: `2.3.0-rc2`
- 主試験環境: Windows / QGIS 3.44.x Solothurn / Python 3.12系
- ZIP構造: 最上位は `MORIZON/` 1フォルダ
- ソース: Python 47ファイル。静的コンパイルは引継ぎ作成時点で成功
- ライセンス: GPL-3.0-only
- 原版: 林野庁委託事業で整備、日本森林技術協会が考え方・作業フローを整理、MIERUNEがQGISプラグインとして実装
- Reloaded: 非公式の互換性対応版。林野庁・日本森林技術協会の公式改修版ではない
- rc2の変更: QGIS 3.44のスケールバーenum対応、CRS確認文の改行修正、集計出力ラベル明確化。計算式・しきい値・判定ロジックの変更なし

## 3. 製品の機能範囲

基本フローは次の5段階。

1. 6要素を作成
2. 各要素を1～3点にスコアリング
3. 収益性・災害リスクを各3～9点として作成
4. 2軸のしきい値から4象限ゾーニング
5. ポリゴン集計・印刷レイアウト作成

6要素は以下。

| 軸 | 要素 | 主入力 | 標準出力 |
|---|---|---|---|
| 収益性 | 地位（スギ・ヒノキ・カラマツ） | NPP、日射係数、凹凸度、DEM | `Y_01_chii_*.tif` |
| 収益性 | 集材作業効率 | DEM、作業システムCSV | `Y_02_shuzai.tif` |
| 収益性 | 地利（到達難易度） | DEM、道路・林道 | `Y_03_chiri.tif` |
| 災害リスク | 地形の複雑さ（SHC） | DEM | `Y_11_chikei.tif` |
| 災害リスク | 傾斜 | DEM | `Y_12_keisha.tif` |
| 災害リスク | 保全対象を含む流域 | DEM、建物 | `Y_13_hozen.tif` |

後段出力は `shuekisei.tif`、`saigairisk.tif`、`params.json`、`zoning.tif`、`thresholds.json`、集計ベクタである。

## 4. 互換性対応の要点

- `PyQt5`直importから`qgis.PyQt`へ移行
- 旧ProcessingアルゴリズムIDとprovider差の吸収
- SAGA依存処理のGDAL/NumPy等への置換
- SHCをGDAL/NumPyで再実装し、QGIS同梱環境でSciPyを必須にしない
- 道路距離を解析DEMと同一グリッドで計算
- 保全対象流域で `grass:r.watershed` / `grass7:r.watershed` を試行
- CRS差を明示的に処理
- WindowsのGeoTIFFロック時に世代付き出力へフォールバック
- QGIS 3.44のレンダラー・enum・レイアウトAPI差に対応

## 5. 入力データとフォルダ契約

操作マニュアルの基本構造を維持する。

```text
ZoningKit_XX/
├─ DATA/
│  ├─ DEM/
│  ├─ ROAD/
│  ├─ SAGYO-SYSTEM_CSV/
│  ├─ SiteIndex/{NPP,SRAD,VTEX}/
│  └─ TATEMONO/
├─ YOUSO/
└─ ZONING/
```

全データは同一のJGD平面直角座標系へ統一し、原則としてDEMのCRSへ合わせる。JGD2000/JGD2011の混在を許容する意味ではなく、データセット内で統一する。

## 6. 引継ぎ時に判明している要確認事項

1. READMEには「metadata.txtではQGIS 3.34以降」とあるが、実際のmetadataは `qgisMinimumVersion=3.44`。文書不整合なので公開前に意図を確定する。
2. `experimental=False` だがrc2はリリース候補。QGIS公式リポジトリ申請前の状態表現を確認する。
3. GRASS Providerが必要な流域処理はクリーン環境での有効化・アルゴリズムID・エラー案内を再確認する。
4. 例外を広く捕捉して継続する箇所が多い。ログとユーザー通知が十分かを、挙動を変えない範囲で監査する。
5. QML文字列内にQGIS 3.16系のversion属性が残る。描画に問題がない限り機械的に変更しない。
6. 自動テスト用の再配布可能な小規模標準データセットが同梱されていない。検証結果の再現性を高めるため、公開可否を確認して整備する価値が高い。

## 8. 推奨する最初の開発順序

1. 同梱資料とソースを読み、`docs/OPEN_ISSUES.md`を更新
2. クリーンQGIS 3.44.xでrc2を無改変のままインストール
3. 起動、6要素、スコアリング、ゾーニング、集計、印刷を順に実行
4. 各段階の入力、パラメータ、出力、ログ、画面、所要時間を記録
5. 失敗があれば最小再現条件を作り、1変更1目的で修正
6. 旧版または受入済み出力と比較
7. README/metadataの対応版不整合等を解消
8. rc3が必要か、または正式v2.3.0へ進むかをユーザーへ提案
