# 検証計画

## 1. 静的確認

```bash
python scripts/static_check.py
python scripts/build_plugin_zip.py
```

静的確認はQGIS実行試験の代替ではない。

## 2. 対象環境

- Windows 10または11
- QGIS 3.44.x Solothurn（64bit、通常インストーラ）
- 新規ユーザープロファイル
- GRASS providerを利用可能にする
- 日本語・空白を含むデータパスとASCIIのみのパスの双方

記録項目: QGIS完全版番号、GDAL、GRASS、Python、OS build、プラグイン版、入力データ識別子、CRS、実行日時。

## 3. スモーク試験

- ZIPからインストールできる
- 有効化・無効化・再有効化できる
- メニューとアイコンから起動できる
- ダイアログを閉じて再度開ける
- QGIS再起動後も起動できる

## 4. 機能試験

| ID | 処理 | 主な合格条件 |
|---|---|---|
| E01 | 地位3樹種 | 3出力、同一グリッド、妥当なNoData |
| E02 | 集材作業効率 | CSVを解釈し整数カテゴリを出力 |
| E03 | 地利 | 道路からの距離関係が正しい |
| E04 | SHC | 旧版/基準出力との相関・差分を記録 |
| E05 | 傾斜 | 単位、範囲、グリッドを確認 |
| E06 | 保全対象流域 | GRASS処理、CRS、建物交差、NoDataを確認 |
| S01 | スコアリング | 各軸3～9点、params.json生成 |
| Z01 | ゾーニング | 4クラス、thresholds.json生成 |
| A01 | 集計 | 入力ポリゴンに統計属性が追加 |
| P01 | 印刷 | ゾーニング/統計レイアウトが作成される |

## 5. 回帰試験

各GeoTIFFについて、サイズ、geotransform、CRS、NoData、データ型、最小/最大、カテゴリ別画素数、差分率、相関係数を保存する。カテゴリ出力は相関だけでなく一致率と混同行列を使う。

合格閾値は旧版との差の原因を説明できるまでは固定しない。既報値を自動的な合格基準にしてはならない。

## 6. 異常系

- CRS未定義/不一致
- 必須ファイル欠落、同候補複数、破損CSV
- 1m/5m/10m DEM、大規模DEM
- 出力ファイルをQGISで開いたまま再実行
- 書込権限なし、長いパス、日本語、空白、OneDrive配下
- GRASS providerなし
- 処理キャンセル後の再実行

## 7. 安定化修正の試験（O-04/O-09/O-11/O-12/O-14）

Claude Code引継ぎ後に追加した、プリフライトチェックとWindowsファイルロック処理統一の確認。いずれも計算式・CRS処理・グリッド整合ロジック自体は変更していないため、**既存の正常系動作に影響が無いこと（回帰）**の確認が特に重要。

| ID | 前提条件 | 操作 | 期待結果 |
|---|---|---|---|
| ST01 | QGISの「プラグインの管理とインストール」でGRASSプロバイダーを無効化 | 保全対象流域にチェックを入れて要素計算を実行 | 他の要素計算が始まる前に「GRASS Processing Provider」警告ダイアログが表示され、処理が中断する（他要素の計算時間を無駄にしない） |
| ST02（回帰） | GRASSプロバイダー有効 | ST01と同じデータで保全対象流域を実行 | 警告ダイアログが出ずに、従来通り保全対象流域が生成される |
| ST03 | DEMと既設路網データに異なるCRSを設定したテストデータ | 地利にチェックを入れて実行 | 「地利計算のCRS確認」警告に、DEM・道路それぞれの実際のCRS（authid）が正しく表示される。「いいえ」で中断、「はい」で続行し、その後distance.py側の既存チェックでRuntimeError（従来通り）になることを確認 |
| ST04（回帰） | DEMと既設路網が同一CRS | 地利計算を実行 | 警告が出ずに、従来通り地利ラスターが生成される |
| ST05 | NPP/SRAD/VTEXのいずれかをDEMと異なる解像度またはCRSにしたテストデータ | 地位指数にチェックを入れて実行 | 「地位指数計算の入力データ確認」に、DEMと差異のある項目（NPP/SRAD/VTEX）の具体的なCRS値・解像度値が表示される。「はい」で続行すると地位指数3出力が正常に生成される（自動整合で処理自体は成功する） |
| ST06（回帰） | 通常のZoningKitデータ（解像度・CRSが揃っている） | 地位指数計算を実行 | 診断ダイアログが出ずに、従来通り3出力が生成される |
| ST07 | 地位指数・地利の既存出力をレイヤパネルに読み込んだままにする | 要素計算を再実行（上書き確認は「はい」） | 従来はここでエラー停止していたが、`_v2`等の世代付きファイルとして新規保存され、処理が正常に完了する（`savearea`と同じ挙動になっていることを確認） |
| ST08（回帰） | 通常起動 | プラグインを有効化し、メニュー・ツールバーから起動 | 従来通りエラーなく起動する（`processes/__init__.py`のtry/except変更が正常系の起動を妨げていないこと） |

ST01・ST03・ST05は、意図的に異常条件を作ってダイアログの表示内容・ボタン挙動を確認する試験であり、実際の計算結果の正誤を見るものではない。ST02・ST04・ST06・ST08は、今回の変更が既存の正常系に悪影響を与えていないことを確認する回帰試験であり、機能試験（E01・E03等）と合わせて実施すること。
