about=MORIZON Reloaded — Forest Zoning.
    林野庁の委託事業を通じて開発された森林ゾーニング支援ツール「もりぞん（MORIZON）」を、現在のQGIS環境で利用できるよう再実装した非公式プラグインです。

    オリジナル版が採用する「林業の収益性」と「山地災害リスク」の両面から森林管理の方向性を検討する考え方と、基本的な処理体系を継承しています。そのうえで、QGIS 3.44への対応、利用できなくなった旧処理の再構築、処理の安定化および操作性の改善を行っています。

    謝辞：オリジナル版は、林野庁の委託事業において、日本森林技術協会がゾーニングの考え方と作業フローを取りまとめ、MIERUNEがQGISプラグインとして実装したものです。オリジナル版の開発に携わった皆様に感謝いたします。

    MORIZON Reloaded is an unofficial compatibility port of the original MORIZON forest zoning plugin for QGIS 3.44, developed by Yoichi Wada as a personal technical initiative. It is not an official modification by the Japan Forest Technology Association or the Forestry Agency of Japan.

    Acknowledgements: The original MORIZON was developed through a project commissioned by the Forestry Agency of Japan, with the zoning workflow organized by the Japan Forest Technology Association and the QGIS plugin implemented by MIERUNE.

changelog=Version 2.3.0-rc3-dev12 (test build, not yet released)
    - Fixed (O-21): get_initial_thresholds() (threshold Quantile init,
      shared by the scoring tab and zoning tab) now caches its result
      per (layer id, classes_count) in-process. On-device dev11 logs
      showed 災害リスク/保全対象を含む流域's Quantile threshold being
      recomputed 7x in a row every time element calculation finished
      (confirmed twice, identically), because dev8's dedup only covers
      scoring_objs_dict's 5 threshold-adjustable elements and savearea
      is not one of them. The new cache is keyed by layer id, so it
      closes the gap regardless of which UI combobox transiently
      re-queries the same layer. Harmless on sample data (0.0-0.1s per
      call) but could matter on large rasters. Not yet verified
      on-device.
    - No analysis formulas, thresholds, NoData rules, CRS treatment,
      output names, or the dev8 same-combobox dedup were changed; this
      is a pure performance/duplicate-work fix at a lower shared layer.

    Version 2.3.0-rc3-dev11 (test build, not yet released)
    - Fixed: the dialog header's build label (branding.py BUILD_LABEL) was
      hardcoded to "v2.3.0-rc3-dev5" and never updated since dev5, despite
      metadata.txt advancing through dev6-dev10. It now reads the version
      from metadata.txt at import time, so it can no longer drift from the
      actual installed version.
    - Diagnostic only: get_quantile_renderer() now logs the computed
      Min/Max and resulting shader item count. On-device (dev10 test),
      収益性/集材作業効率's scoring QML generation failed with "QML内に
      連続値カラーランプ（colorrampshader/item）が見つかりません" right
      after the O-18 fix let it reach this step for the first time ever
      (previously masked by the Permission Denied failure). Root cause
      not yet confirmed; this logs the actual values for next time (O-19).
    - O-18 (集材作業効率 lock fallback) is confirmed fixed by this same
      on-device run: no more "Deleting ... failed: Permission denied";
      the write succeeded and it failed one step later, at QML styling.

    Version 2.3.0-rc3-dev10 (test build, not yet released)
    - Fixed: 収益性/集材作業効率(cost.py) now uses the same Windows file-lock
      fallback as siteidx/distance/savearea/shc/zoning (resolve_writable_output_path,
      versioned _v2/_v3 output). Previously it called gdal.Create() directly on
      the existing path; re-running element calculation while the prior
      集材作業効率 output was still loaded in QGIS always failed with
      "Deleting ... failed: Permission denied", confirmed 3x on-device
      (dev9 testing session). This had a cascading effect: the stale
      cost output then caused profit.py's grid-mismatch error in scoring.
    - On-device (dev9): O-17's Info/Warning classification held up
      correctly through this failure cascade (tests A and B both passed
      on real hardware). Tests E (count_NODATA) and F (threshold-init
      dedup) were not exercised this run (no NODATA column produced;
      every retry created new versioned layers, so the dedup's
      same-layer-id skip was never triggered).

    Version 2.3.0-rc3-dev9 (test build, not yet released)
    - Changed: UI-stall warnings that don't overlap any MORIZON timed() span
      and occur while the MORIZON dialog is closed and no MORIZON thread is
      running are now logged as Info instead of Warning, with a wording
      that says it's unrelated to MORIZON. A cumulative count+total-seconds
      line is logged alongside each one. Stalls that overlap a MORIZON span,
      or happen while the dialog is open or a MORIZON thread is running,
      remain Warning as before. Addresses a report of a 39-hour run of
      another plugin producing dozens of MORIZON Warning lines (up to
      ~39000s each) for stalls MORIZON had no part in.
    - No analysis formulas, thresholds, NoData rules, CRS treatment, output
      names, or the watchdog's detection method (250ms QTimer, 2.0s
      threshold) were changed.
    - Verified with a pure-Python stub test (not real QGIS) covering the
      four branch combinations and the cumulative counter; not yet
      exercised on-device.

    Version 2.3.0-rc3-dev8 (test build, not yet released)
    - Fixed: init_scoring_rlayer_stats() (threshold Quantile init) no longer
      re-runs bandStatistics() for a layer it already initialized; the
      element-calculation finish step was calling it ~50-60 times for the
      same layer (0.0s each on the sample data, a plausible hang cause on
      large rasters). Not yet verified on-device.
    - Diagnostic only: added timed() spans around plugin __init__/initGui,
      and a fallback hint (last completed span + how long before the stall)
      when the UI-stall watchdog finds no overlapping span, to help find
      whether a startup-time stall (O-15, unconfirmed, separate from the
      QgsProject.instance() fix) is inside MORIZON or not. No behavior change.

    Version 2.3.0-rc3-dev7 (test build, not yet released)

    - On-device (dev6): confirmed the O-15 UI-thread stall is resolved
